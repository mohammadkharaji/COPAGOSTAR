# نبض فروش — کوپا گستر (نسخهٔ سرور اوبونتو)

داشبورد فروش فارسی و راست‌به‌چپ برای داده‌های فروش سال ۱۴۰۵. مبالغ به ریال و تاریخ‌ها جلالی هستند. هستهٔ پیش‌فرض «کوپا گستر» است و «زنجیره‌ای» جدا نمایش داده می‌شود.

این نسخه روی سرور لینوکس اجرا می‌شود و به Excel نیاز ندارد؛ فایل‌های استخراج‌شده (`sr_*.tsv`) از پوشهٔ `data/raw` خوانده و در DuckDB بارگذاری می‌شوند.

## امکانات

- نمای کلی، روند روزانه و ماهانه، آنالیز رشد و افت
- شعب و مناطق، کالا و برند، تحلیل شعبه و برند
- تحلیل پارتو، تحلیل فاکتور (تعداد و میانگین سطر فاکتور، توزیع برحسب مبلغ)
- پروفایل مشتری و پروفایل ویزیتور
- سلامت داده و نمایش محدودیت‌های شناخته‌شدهٔ داده

## ساختار

| مسیر | محتوا |
|---|---|
| `backend/` | API با FastAPI و DuckDB، همراه تست‌ها |
| `frontend/` | رابط کاربری React، Vite و Recharts |
| `scripts/sync.py` | پایش `data/raw` و بارگذاری فایل‌های جدید در دیتابیس |
| `deploy/` | فایل‌های سرویس systemd |
| `install.sh` | نصب و به‌روزرسانی روی اوبونتو |
| `data/` | دیتابیس و فایل‌های خام (داخل گیت نیست) |

## نصب روی اوبونتو (۲۲٫۰۴ به بالا)

```bash
git clone https://github.com/mohammadkharaji/COPAGOSTAR.git
cd COPAGOSTAR
sudo bash install.sh --data /path/to/sr.duckdb
```

اسکریپت `curl` و `rsync` را نصب می‌کند و در صورت نبود، Node.js ۲۲ و `uv` را هم نصب می‌کند. سپس برنامه را در `/opt/sr` می‌گذارد، فرانت‌اند را می‌سازد و دو سرویس را راه می‌اندازد:

- `sr-api`: داشبورد و API روی پورت ۸۰۰۰
- `sr-sync`: پایش `/opt/sr/data/raw`

گزینه‌ها:

- `--data <فایل>`: دیتابیس آماده را در `/opt/sr/data/sr.duckdb` می‌گذارد
- `--port <عدد>`: پورت را عوض می‌کند

اجرای دوبارهٔ همین دستور، برنامه را به‌روز می‌کند و داده‌های `/opt/sr/data` را پاک نمی‌کند.

بعد از نصب، داشبورد در `http://<آدرس-سرور>:8000` باز می‌شود و بدون ورود هیچ داده‌ای نمایش نمی‌دهد.

## ورود

- نام کاربری پیش‌فرض `admin` است (با `SR_ADMIN_USER` قابل تغییر).
- رمز عبور هنگام اولین نصب پرسیده می‌شود، یا با متغیر `SR_ADMIN_PASSWORD` داده می‌شود. فقط هش `scrypt` آن در `/etc/sr/auth.env` (فقط‌خواندنی برای root) ذخیره می‌شود و داخل گیت نیست.
- اجرای دوبارهٔ `install.sh` رمز را نگه می‌دارد؛ برای تغییر رمز، آن را با `SR_ADMIN_PASSWORD=<رمز جدید>` اجرا کنید.
- همهٔ مسیرهای `/api` بدون نشست معتبر `401` می‌دهند. نشست ۱۲ ساعت اعتبار دارد و بعد از ۵ تلاش ناموفق، آدرس مهاجم ۱۵ دقیقه مسدود می‌شود.

> هشدار: این سرور هنوز TLS ندارد و ورود روی HTTP ساده انجام می‌شود، یعنی رمز بدون رمزنگاری روی شبکه می‌رود. برای استفادهٔ واقعی، پشت یک دامنه و HTTPS (مثلاً Caddy) بگذارید و `Environment=SR_COOKIE_SECURE=1` را به `sr-api.service` اضافه کنید.

## به‌روزرسانی روی سرور

تغییرات جدید را از GitHub بگیرید و دوباره نصب کنید:

```bash
cd /root/COPAGOSTAR
git pull --ff-only
sudo bash install.sh
```

- `git pull --ff-only` فقط وقتی کار می‌کند که روی سرور تغییر دستی نداده باشید. اگر خطا داد، ابتدا `git status` را بررسی کنید.
- `install.sh` کد را در `/opt/sr` به‌روز می‌کند، وابستگی‌ها و فرانت‌اند را دوباره می‌سازد و سرویس‌ها را ری‌استارت می‌کند. در این مدت چند ثانیه تا چند دقیقه قطعی کوتاه طبیعی است.
- پوشهٔ `/opt/sr/data` (دیتابیس، فایل‌های `raw` و فایل Excel) و رمز ورود (`/etc/sr/auth.env`) تغییر نمی‌کنند.
- بعد از به‌روزرسانی وضعیت سرویس‌ها را ببینید و داشبورد را با Ctrl+F5 باز کنید:

```bash
systemctl status sr-api sr-sync --no-pager
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8000/api/overview
```

پاسخ `401` یعنی API فعال است و ورود اجباری کار می‌کند.

## داده

فایل‌های داده در گیت نیستند. دو راه برای دادن داده:

1. دیتابیس آماده با `--data` هنگام نصب.
2. فایل‌های `sr_<هسته>_<سالماه>.tsv` (مثلاً `sr_kg_140507.tsv`) را در `/opt/sr/data/raw` بگذارید؛ `sr-sync` تغییر را تشخیص می‌دهد و فایل‌های جدید را بارگذاری می‌کند. فایل بدون تغییر دوباره بارگذاری نمی‌شود.

دکمهٔ «به‌روزرسانی» در رابط، همان همگام‌سازی را یک‌بار اجرا می‌کند.

## تنظیمات (متغیرهای محیطی)

| متغیر | کاربرد | پیش‌فرض |
|---|---|---|
| `SR_DATA_DIR` | پوشهٔ داده | `<پروژه>/data` |
| `SR_RAW_DIR` | پوشهٔ فایل‌های `.tsv` | `<SR_DATA_DIR>/raw` |
| `SR_DB_PATH` | فایل دیتابیس | `<SR_DATA_DIR>/sr.duckdb` |
| `SR_HOLIDAYS` | تعطیلات اضافه با تاریخ جلالی، جداشده با کاما، مثل `1405/08/05,1405/08/12` | خالی (جمعه‌ها همیشه تعطیل‌اند) |

برای تغییر متغیرها، خط `Environment=` را در `/etc/systemd/system/sr-api.service` ویرایش کنید و سپس `systemctl daemon-reload && systemctl restart sr-api` را بزنید.

## مدیریت سرویس‌ها

```bash
systemctl status sr-api sr-sync
journalctl -u sr-api -n 50
journalctl -u sr-sync -n 50
```

## اجرا برای توسعه

بک‌اند (پایتون ۳٫۱۱ یا بالاتر و `uv`):

```bash
cd backend
uv sync
uv run uvicorn app.api:app --port 8000
```

فرانت‌اند (Node ۲۰٫۱۹ یا بالاتر؛ درخواست‌های `/api` به پورت ۸۰۰۰ هدایت می‌شوند):

```bash
cd frontend
npm ci
npm run dev
```

تست‌ها:

```bash
cd backend
uv run pytest
```

`tests/test_sync.py` از `fcntl` استفاده می‌کند و فقط روی لینوکس اجرا می‌شود.

## معیارهای محاسبه

- «ریال خالص» مطابق Pivot اکسل اصلی محاسبه می‌شود.
- گزارش سطر فاکتور فقط فروش عادی را می‌شمارد: ردیف‌های پروموشن و مرجوعی کنار گذاشته می‌شوند. میانگین سطر فاکتور برابر است با تعداد این ردیف‌ها تقسیم بر تعداد فاکتورهای یکتای فروش عادی.
- شمارندهٔ «تعداد فاکتور» در نمای کلی همهٔ ردیف‌ها را می‌شمارد و تعریفش با مخرج میانگین سطر فاکتور یکی نیست.
- شاخص یا ستونی که در داده نیست، ساخته یا تخمین زده نمی‌شود؛ بخش‌های فاقد داده تأییدشده پنهان می‌شوند.
